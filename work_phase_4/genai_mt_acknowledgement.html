GenAI and Machine Translation Usage Statement & Reflection

Tools Used and Purposes

In this project, I intentionally used Generative AI and machine translation tools to support frontend development and documentation writing. The main tools were:

  • ChatGPT: used to generate and explain JavaScript examples, clarify certain syntax patterns, provide ideas for responsive image layouts, and help me locate and fix several accessibility issues. It was also used to polish the language of this reflection and the Implementation Rationale so that the expression was clearer and more formal.
  • Machine translation tools (such as built-in browser translation or online MT): mainly used to help me understand English materials or double-check the meaning of sentences, but not to directly replace my own writing.

It should be noted that I positioned these tools as assistive tools for development and writing, not as tools to directly produce final deliverables. All content was reviewed and edited by me before submission.

Prompting Style and Interaction Process with AI

In practice, I used multi-turn, multi-step prompting rather than asking AI to write everything in one prompt. My usual workflow was:

  1. First, ask a concrete question, for example: "How can I make my carousel move? I have already written the HTML and CSS. Can you give me some JavaScript examples?"
  2. If the code suggested by AI didn't match the interaction I wanted, or it didn't run at all, I would first try to fix it myself and test it in the browser.
  3. If the problem still existed, I would ask again with the code I had modified, including theerror message,screenshots, or even the full HTML, and ask it to explain: “(About the carousel) Why is the carousel not working after I added the JS? Please explain in detail why thiserror occurs and give examples. (Here is the code I changed.)”

In this project there was a typical case: for the carousel JS, ChatGPT gave me several solutions, but none of them some JavaScript and then spent several days learning it again for this issue. This shows that AI's answers can be used as sources of ideas, but they are not always the final, fully working code.

I used the same method for the login, commenting, and posting features. At first, AI suggested putting them on separate pages, but the scope and structure of this assignment did not allow adding extra pages. So I asked again whether they could be embedded with JavaScript in the existing pages. I finally integrated these features smoothly by combining AI's suggestions, the assignment requirements, and knowledge from other courses.

When dealing with accessibility issues, the first time I used the IBM Equal Access Accessibility Checker I didn't really understand the warnings. I sent the screenshots and HTML to ChatGPT and asked it to "translate" the messages. Most of the time the explanations were straightforward, and I could pass the check quickly by following them. As the project moved forward, I realised I could read many of the errors and HTML/CSS issues by myself and didn't have to ask AI each time. This means the early AI explanations actually played a "teaching/decomposition" role.

Critical Evaluation of AI Outputs

Although AI is convenient, it does make a lot of mistakes — and sometimes they are very "confident" mistakes. So my rule is: every AI suggestion must be verified in both the browser and the code.

  • First, right-click in the browser → Inspect, to see the real DOM structure and CSS.
  • Then compare it with ChatGPT's suggestion and test it temporarily in the DevTools.
  • If the result looks correct, then apply it to the actual source files.

The benefit is that changes made in the browser disappear after refresh, so they will not break the original files, and one wrong AI suggestion will not mess up the whole page.

I also found that letting AI “directly rewrite my code” is actually unreliable: if it doesn't understand what I really want, or if I don't have enough judgement, I may just follow it blindly and waste time, and even start to doubt my own ability.

For example, when I was working on the Share Your Recipes page, one of the cards overflowed the page. I asked ChatGPT and it said the problem was in the header settings. But that didn't make sense, because the issue only happened on this single page — other pages were fine. So I didn't follow that answer, went back to check the CSS myself, and quickly found the real cause.

Out of curiosity, I asked AI again with the corrected code, and it still wouldn't admit the previous answer was wrong. My conclusion is: a web page is an integrated system; even if you give AI screenshots, HTML, and CSS, as long as there is one piece of context it doesn't fully understand, it may still “invent a very reasonable answer” — and say it confidently. This is exactly what we need to be cautious about.

Therefore my current stance is:

  • Web development cannot rely on AI all the time;
  • AI cannot be more careful than you are;
  • Your page structure, class names, and file paths are best understood by you, not by AI.

In terms of colour palettes, AI often suggested options that looked nice but did not meet WCAG 2.2 contrast requirements, so I did not adopt those palettes and adjusted them manually.

When writing the Implementation Rationale and this GenAI reflection, I deliberately choseto let AI help me with polishing and tone, instead of asking it to “summarise everything.” This is because:

  • AI tends to fabricate or over-simplify when summarising;
  • Even if you give it all the files, the summary is often generic and surface-level;
  • I wanted the reflection to show my own decision-making process, not something that “sounds like AI wrote it.”

Problems Encountered and Solutions

The biggest problem I encountered was not “I can't code,” but that AI sometimes gives very fluent, very confident, but actually wrong answers. To deal with this, I summarised a 3-step strategy:

  1. Ask again: if I suspected my prompt was unclear, I cleared the conversation and asked again with a more precise prompt, including context, page structure, and error messages.
  2. Self-check: if AI was still off, I checked HTML/CSS/JS myself, especially common mistakes like wrong class names, missing file imports, wrong paths, or conflicting styles.
  3. Ask the teaching team: if I had already tried AI + self-debugging and it still didn't work, I asked the course teaching team to confirm whether the issue was caused by assignment constraints, browser environment, or the project structure.

This order helps me avoid blindly trusting AI while also not overusing teaching resources.

Impact on Efficiency and Creativity

Even with the above issues, AI still improved my overall efficiency. Especially in the early stage when I was not very familiar with CSS, ChatGPT helped me:

  • shorten long and repetitive CSS;
  • remind me which styles could be abstracted into shared utilities;
  • give layout ideas (responsive image grids, card layouts, embedded sections).

This allowed me to spend more time on parts that really needed my own judgement, such as interaction logic, page structure, and how to integrate login/comment/post features into the existing pages.

Most of the time I didn't open many AI tools at once — I mainly used ChatGPT to draft structure, generate/adjust code, and polish language. This kept both the technical part and the writing style consistent, and made it clear in the documentation where AI was used.

For me, the most valuable part of AI was that when I couldn't understand other people's CSS/JS, it could first explain it in words I understood. After that, I didn't need to ask AI for every single step.

Future Professional Use and Ethical Reflection

This project made it clearer to me that AI works best in an assist/augment role, not a replace role. Well-designed prompts can significantly improve output quality and help me understand things I used to just copy, such as JS event handling, DOM operations, layout grids, and ARIA/Accessibility semantics.

In future work I will:

  • Write prompts more strategically, with task, context, and goals;
  • Clearly document where AI / MT was used, for what purpose, and whether it was edited;
  • Keep reflecting on ethical issues such as bias, inclusiveness, transparency, originality, and attribution;
  • Always manually verify AI outputs before using them, especially for accessibility standards, assignment requirements, code safety, and WCAG contrast.

Integrity Statement

I confirm that all use of Generative AI and Machine Translation tools in this assignment was in accordance with the course's GenAI and MT Usage Framework. At no point did I submit unreviewed AI output. All AI-generated code, explanations, text, and structural suggestions were judged, tested, and edited by me before being integrated into the final project. I treated AI as a tool for learning, assistance, and efficiency, not as a tool to complete the assignment on my behalf, and I take full responsibility for the accuracy, originality, and academic integrity of the final work.
